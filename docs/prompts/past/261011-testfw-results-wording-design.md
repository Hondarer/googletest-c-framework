# testfw のテスト結果の見出しと確認項目の区分表示 最終仕様

検討 ID: testfw-results-wording

版: 1

状態: 承認済み (2026-10-11 Tetsuo Honda)

上流文書: `prompt/testfw-results-wording-discussion.md` (版 4)

## 目的

`framework/testfw` が出力する個別結果 (`results.md`) のテスト項目節を、読み手に分かりやすい見出しにし、各確認項目が正常系と異常系のどちらの確認かを項目ごとに示します。

## 範囲

### 対象

Table: 変更の対象

| 対象 | 内容 |
| --- | --- |
| 個別結果の見出し | `## テスト項目` と `### 確認内容` の名前 |
| 確認節の項目 | 区分 (正常系、異常系) の表示 |
| 言語 | C/C++ と .NET (共通の生成処理) |
| 出力 | 個別結果、パラメーター テストの定義単位とレコードのファイル、テスト実行時のコンソールに表示するテスト項目の要約 |
| 文書 | `framework/testfw/docs/about-test-phase.md`、`test-subprocedures.md`、`how-to-test.md`、`app/general/docs/dotnet-test-results-design.md`、`framework/makefw/docs/subfolder-compilation.md` |

### 対象外

- `### 状態`、`### 手順`、`### 確認件数合計` の見出し
- 全体サマリー (`summary.md`) の見出しと表
- 確認タグの記法と件数の集計規則
- 見出し以外で「テスト項目」を指す文 (文書の本文、パラメーター テストのレコードのファイルの「テスト項目は [テスト定義の結果](...) を参照してください。」)
- `app/general/docs/dotnet-test-results-design.md` の「Markdown 化以前の設計と検証記録」節

## 見出し

Table: 見出しの変更

| 現行 | 変更後 |
| --- | --- |
| `## テスト項目` | `## テスト項目の詳細` |
| `### 確認内容 (<件数>)` | `### 確認 (<件数>)` |
| `### 確認内容_N (<件数>)` | `### 確認_N (<件数>)` |

- `## テスト項目の詳細` は、テスト項目サマリーがある場合、テスト項目がない場合 (本文「なし」)、エビデンス生成に失敗した場合 (`> [!CAUTION]`)、パラメーター テストのレコードのファイル (定義単位ファイルへのリンク) のすべてで使います。
- 件数の括弧書き (例: `(正常系:2, 異常系:1)`、`(0)`、`(未評価)`) は現行どおりです。

## 確認項目の区分

### 区分を付ける項目

`[確認_正常系]`、`[確認_異常系]`、`[Pre-Assert確認_正常系]`、`[Pre-Assert確認_異常系]` に由来する項目の先頭に、区分を付けます。

Table: 区分を付ける項目と表示

| 項目 | 区分の表示 |
| --- | --- |
| `[確認_正常系]`、`[Pre-Assert確認_正常系]` | `【正常系】` |
| `[確認_異常系]`、`[Pre-Assert確認_異常系]` | `【異常系】` |
| `[状態確認]` | 付けない (現行どおり括弧で囲む) |
| サブ手順の親項目 | 付けない |

- 区分は箇条書きの記号の直後に置き、区分と説明文の間に空白を入れません。
- 回数の表記 (`〔2 回〕` など) は、現行どおり項目の末尾に付けます。
- サブ手順の子項目の区分は、件数の集計と同じ区分です。参照に `区分` 属性がある場合は、その指定 (入れ子では内側の指定を優先) を反映します。

> [!NOTE]
> 件数に数える確認タグは、必ず正常系か異常系のどちらかに分類されます。区分のないタグは解析エラーになるため、区分のない確認項目は出力されません。

### 表示例

指摘箇所 `app/calc/test/src/cmd/addTest/results/addTest.help/results.md` の表示:

```markdown
## テスト項目の詳細

help オプションで必須位置引数なしでも正常終了することの確認

### 状態

- help オプションを指定する。

### 手順

- help オプションで main() を呼び出す。

### 確認 (正常系:1)

- 【正常系】必須位置引数なしでも正常終了すること。
```

サブ手順と回数を含む表示:

```markdown
### 確認 (正常系:4, 異常系:1)

- サブ手順 exportTest.SetUp にて以下を確認する。
    - (`workspace_root.empty()` が false であること。)
- 【正常系】mock_write が呼ばれること。〔2 回〕
- サブ手順 testing.expectExportNamesMatch にて以下を確認する。
    - 【正常系】`missing.empty()` が true であること。
    - 【正常系】`extra.empty()` が true であること。
- 【異常系】不正な引数でエラーを返すこと。
```

## 文書の更新

- 出力の見出しを示した例 (コード ブロック、表) を、変更後の見出しと区分の表示に合わせます。
- 本文で節を指す「確認内容」(「`### 確認内容` セクション」「確認内容節」など) を「確認」(「`### 確認` セクション」「確認節」など) に言い換えます。
- 本文の「テスト項目」「テスト項目サマリー」などの語は変更しません。
- `test-subprocedures.md` の「各項目にラベルは付けません」は、経路などのラベルを付けないという意味が伝わるように、区分の表示と矛盾しない記載にします。
- 区分の表示規則 (この文書の「確認項目の区分」節) を `about-test-phase.md` に記載します。
- 文書には変更の経緯を記載しません。

## 作業の進め方

コーディングとテストは、codex CLI 経由で gpt-6.1-sol (reasoning effort: medium) に依頼します。Claude は差分のレビューと仕様との照合を行います。

## 受入条件

1. `addTest.help` の `results.md` が、表示例のとおり `## テスト項目の詳細`、`### 確認 (正常系:1)`、`- 【正常系】必須位置引数なしでも正常終了すること。` で出力されること。
2. 異常系、Pre-Assert、サブ手順 (区分の上書きを含む)、マルチ フェーズ テストで、各確認項目に正しい区分が付き、`[状態確認]` とサブ手順の親項目には付かないこと。`### 確認件数合計` が変わらないこと。
3. エビデンス生成の失敗、パラメーター テストのレコード、テスト項目のないテストでも、見出しが `## テスト項目の詳細` であること。レコードのファイルの「テスト項目は … を参照してください。」の文が変わらないこと。
4. `framework/testfw/bin_test/` の局所テストがすべて成功し、追加したテストが 1〜3 を検証すること。
5. `framework/testfw`、`app/calc`、`app/calc.net/test` の `make test` が成功し、`.warn` に今回の変更に起因する警告がないこと。
6. 変更した文書が「文書の更新」節のとおりで、`text_style_jp.py --dry-run` で差分なしであること。
