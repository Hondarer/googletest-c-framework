# testfw のテスト結果におけるサブ手順表示と空行 最終仕様

検討 ID: testfw-subprocedure-display

版: 2

状態: 承認済み (2026-10-11 Tetsuo Honda)

上流文書: `prompt/testfw-subprocedure-display-discussion.md` (版 13)

## 目的

`framework/testfw` が出力する個別テスト結果 (`results.md`) のテスト項目節を、テストの処理の流れを読み手に説明できる構成にします。  
サブ手順に由来する項目は、各項目に付けていたラベル `〔サブ手順 <経路>、内部サイクル=<n>、参照回数=<式>〕` の代わりに、入れ子の箇条書きで示します。テスト コード節では、プラットフォーム条件分岐の除去で生じる連続空行をまとめます。

## 範囲

### 対象

Table: 変更の対象

| 対象 | 内容 |
| --- | --- |
| テスト項目節 | 状態節、手順節、確認内容節 (サイクル番号付きの節を含む) の項目の並び、入れ子、親項目、回数の表記 |
| テスト コード節 | 連続する空行の圧縮 |
| 言語 | C/C++ と .NET の両方 |
| 出力ファイル | テスト項目節とテスト コード節を持つすべての `results.md` (通常テスト、パラメーター テストの定義単位) |

### 対象外

- 確認件数の集計規則 (見出しの件数、全体サマリーの確認件数の値)
- テスト ソースの記法 (`[サブ手順]`、`[サブ手順参照]`、確認タグ)。説明文の記法は追加しません。
- 既存のテスト ソース
- 実行結果節、全体サマリーの表の構成

## テスト項目節の表示規則

### 入れ子

状態節、手順節、確認内容節のすべてで、サブ手順に由来する項目を、その参照を表す親項目の下の子項目として表示します。  
サブ手順の中で別のサブ手順を参照している場合は、内側の参照の親項目を外側の親項目の子項目とし、その項目を孫項目以下として表示します。  
入れ子の字下げは、1 階層あたり半角空白 4 個です。

子項目には `〔〕` のラベル (経路、内部サイクル、参照回数) を付けません。  
`[状態確認]` の子項目は、サブ手順外と同じく括弧で囲みます (例: ``- (`workspace_root.empty()` が false であること。)``)。

### 親項目の文言

Table: 子項目がある親項目の文言

| 節 | 親項目の文言 |
| --- | --- |
| 状態 | サブ手順 <名前> にて以下を準備する。 |
| 手順 | サブ手順 <名前> を実施する。 |
| 確認内容 | サブ手順 <名前> にて以下を確認する。 |

子項目がない親項目は、どの節でも「サブ手順 <名前> を実施する。」とします。  
<名前> は、その階層で参照したサブ手順の名前です。経路 (`A → B`) は入れ子の階層で表すため、親項目には書きません。

### 親項目を出す単位と条件

親項目は、サブ手順の参照 1 回ごとに出します。同じサブ手順を複数回参照した場合も、参照ごとに別の親項目になります。

参照を書いたフェーズに対応する節には、子項目の有無に関わらず親項目を必ず出します。

Table: 参照を書いた位置と親項目を必ず出す節

| 参照を書いた位置 | 親項目を必ず出す節 |
| --- | --- |
| テスト本体の前 (`SetUp` など) | 最初のサイクルの状態節の先頭 (Arrange の項目より前) |
| Arrange | 状態節 |
| Act、Pre-Assert | 手順節 |
| Assert | 確認内容節 |
| テスト本体の後 (`TearDown` など) | 最後のサイクルの手順節の末尾 (最後の Act の最終ステップ) |

- それ以外の節には、その節に子孫の項目がある場合だけ親項目を出します。
- サブ手順の中に書いた参照は、外側の参照と同じフェーズに属します。
- 外側のサブ手順自身の項目がなく、内側のサブ手順の項目だけがある場合も、外側の親項目を出します。

> [!NOTE]
> フェーズと節の対応は、Arrange が状態、Act が手順、Assert が確認という各フェーズの役割に合わせたものです。テスト本体の前の参照は事前の準備として状態節に、テスト本体の後の参照は最後の操作として手順節に置きます。

### 回数

回数は、1 以外のときだけ既存の形式で項目の末尾に付けます。

Table: 回数を付ける対象と表記

| 対象 | 付ける回数 | 表記の例 |
| --- | --- | --- |
| 親項目 | 参照の回数 (`[サブ手順参照]` の `回数`) | `〔3 回〕`、`〔4 回: PARAM、PARAM=4〕` |
| サブ手順内の子項目 | サブ手順 1 回あたりの確認タグの回数 | `〔2 回〕` |
| サブ手順外の項目 | 確認タグの回数 (現行の規則のまま) | `〔12 回: PARAM*3、PARAM=4〕` |

- 「1 以外」は評価した値で判定します。値が 0 の場合は `〔0 回〕` を付けます。
- 一部のレコードだけを実行して回数を評価できない場合は、式が `1` 以外のときに `〔未評価: <式>〕` を付けます。
- `[状態]`、`[手順]`、`[状態確認]` の子項目は件数に数えないため、回数を付けません。
- サブ手順外の確認タグに明示した回数式は、現行どおり `1` でも `〔1 回〕` を付けます。
- 見出しの件数には、現行どおり経路上の回数の積を加算します。

> [!NOTE]
> 親項目と子項目に回数を分けて付けることで、親項目の回数はソースの `[サブ手順参照 … 回数=3]` に、子項目の回数はサブ手順内の確認タグに、それぞれ 1 対 1 で対応します。

### 並び順

各節の中の項目は、テスト コードのフェーズの順に並べます。

1. テスト本体の前に書いた参照 (`SetUp` など。最初のサイクルだけ)
2. Arrange
3. Act
4. Pre-Assert
5. Assert
6. テスト本体の後に書いた参照 (`TearDown` など。最後のサイクルだけ)

- 同じフェーズの中は、テスト コード上の順に並べます。現行の種類別のまとめ方 (手順節: `[手順]` → `[Pre-Assert手順]`、確認内容節: `[状態確認]` → `[Pre-Assert確認]` → `[確認_*]`) は廃止します。
- サブ手順の中の項目は、参照を書いたフェーズに属します。親項目の下では、サブ手順の中のフェーズ コメントに関係なく、テスト コード上の順に並べます。
- テスト本体の中で最初のフェーズ コメントより前にある項目は、Arrange に属します。フェーズ コメントのないテストでは、すべての項目がテスト コード上の順に並びます。
- 複数サイクル (`Act_2` など) のテストでは、サイクルごとの節の中で同じ規則を適用します。

> [!NOTE]
> Pre-Assert には、Act の実行中に働くモックの期待と動作を書きます。Pre-Assert の項目を Act の直後に置くことで、「操作する。その中で次のことが行われる。」という処理の流れとして読めます。  
> 並び順はテスト コード上の記載から決め、実行時の呼び出し順は記録しません。モックの動作として登録したラムダの中の参照は、実際には Act の中で実行されますが、記載した位置 (Pre-Assert) に並びます。

## テスト コード節の空行

テスト コード節に掲載するコード (テスト本体、パラメーターのインスタンス化、サブ手順の定義) で、2 行以上連続する空行を 1 行にまとめます。  
空行の由来 (プラットフォーム条件分岐の除去、元のソースの空行) は区別しません。

> [!NOTE]
> 条件分岐を空行に置き換える処理は、抽出処理の中で元ソースと行番号をそろえるために残します。サブ手順の「定義元」の行番号は元ソースから取るため、空行をまとめても変わりません。

## 実装方針

Table: 変更するファイルと内容

| ファイル | 変更内容 |
| --- | --- |
| `framework/testfw/bin_internal/test_subprocedures.py` | `expand` が出力する中間ソースで、ラベルの代わりに参照の開始と終了 (サブ手順名、参照の回数) を表す情報を渡す。`report` でテスト コード節の連続空行をまとめる |
| `framework/testfw/bin_internal/test_summary.py` | `render_summary` で項目をフェーズとテスト コード上の順に保持し、参照の範囲から入れ子と親項目を組み立てる。回数の表記規則を適用する |
| `framework/testfw/bin_test/` の該当テスト | 期待値の更新と、本仕様の規則を確認するテストの追加 |
| `framework/testfw/docs/test-subprocedures.md` | 結果の表示 (入れ子、親項目の文言、回数) の記載 |
| `framework/testfw/docs/about-test-phase.md` | テスト項目節の並び順、サブ手順の表示、テスト コード節の空行の記載と出力例の更新 |

中間ソースの具体的な形式は実装で決めます。ただし、確認タグとして解釈される既存の書式と衝突しないこと、C/C++ と .NET で同じ処理を通ることを条件とします。

## 検証

### 単体テスト

`framework/testfw/bin_test/` で次を確認します。

- 状態節、手順節、確認内容節の入れ子と、節ごとの親項目の文言
- 入れ子のサブ手順による孫項目と、外側に項目がない場合の外側の親項目
- 同じサブ手順の複数回の参照で、参照ごとに親項目が出ること
- 参照を書いた位置 (テスト本体の前、Arrange、Act、Pre-Assert、Assert、テスト本体の後) ごとに、親項目を必ず出す節が正しいこと
- 対応する節以外で、子孫の項目がない親項目が出ないこと
- 子項目がない親項目が「を実施する。」の文言になること
- 複数サイクルで、テスト本体の前の参照が最初のサイクル、テスト本体の後の参照が最後のサイクルに出ること
- 回数: 親項目の 1 以外の回数、子項目の 1 以外の回数、`PARAM` を含む回数、回数 1 の省略、見出しの件数
- フェーズ順の並び (Pre-Assert の項目が Act の項目の後に並ぶこと)
- テスト コード節の連続空行の圧縮
- .NET の経路 (`test_dotnet_path_spaces.py` のサブ手順と `回数=2` の参照)
