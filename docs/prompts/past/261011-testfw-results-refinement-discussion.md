## 調査結果

### BL-001 の再現

`app/calc/test/src/libcalcTest/exportTest/results/exportTest.symbol_names_match/results.md` のテスト項目節に、説明コメント「libcalc のエクスポート シンボル名が API 表と一致することの確認」がないことを確認しました。

```cpp
// libcalc のエクスポート シンボル名が API 表と一致することの確認
// [サブ手順参照 名前=exportTest.SetUp]
TEST_F(exportTest, symbol_names_match)
```

CodeBlock: 再現するテスト ソース

`test_summary.py` の `render_summary` は、テスト定義より前で、タグを含むコメントまたはコメント以外の行を見つけると、集めた説明 (`desc`) を破棄します (`framework/testfw/bin_internal/test_summary.py` の 249〜260 行)。参照を展開した行がこれに該当します。

### 現行の出力

個別結果 (C/C++) の先頭は次のとおりです (`results_markdown.py` の `individual`)。

```markdown
# exportTest.symbol_names_match

- 判定: PASSED
- テスト バイナリ: bin/exportTest
- 備考: `<コメント>`          ← コメントがある場合のみ
```

CodeBlock: 現行の個別結果の先頭

全体サマリーの先頭は `- 開始日時: <LANG=C の date 出力>` (例: `Sat Jan 24 07:55:31 JST 2026`) です。値は `exec_test_c_cpp.sh` と `exec_test_dotnet.sh` がジャーナルに書いた `Test start on <date>.` 行から取り出しています。

状態、手順、確認内容の本文が空の場合は「なし」を出力します (`test_summary.py` の 362〜368 行)。

### プラットフォーム条件の評価

プラットフォーム条件の評価は 2 か所にあり、どちらも `#if defined(PLATFORM_WINDOWS)` / `#if defined(PLATFORM_LINUX)` と同形の `#elif` だけを評価します。

Table: プラットフォーム条件を評価する処理

| 処理 | 対象 |
| --- | --- |
| `get_test_code_c_cpp.awk` | テスト本体 |
| `test_subprocedures.py` の `platform_lines` | サブ手順 (fixture の `SetUp`、共通関数など) |

`PLATFORM_*` は `app/cplat/prod/include/cplat/base/platform.h` が `_WIN32` と `__linux__` から定義するマクロで、cplat に依存しない testfw 自身のコードでは使えません。testfw 自身のテスト コードとライブラリでは、次の書式が使われています。

Table: testfw と app のテスト コードにある _WIN32 の書式別件数

| 書式 | 件数 |
| --- | --- |
| `#ifndef _WIN32` | 146 |
| `#ifdef _WIN32` | 67 |
| `#if !defined(_WIN32)` | 6 (app 側を含む) |
| `#if defined(_WIN32)` | 1 (app 側を含む) |

`LINUX` という名前のマクロは、makefw のコンパイル フラグ (`DEFINES`、`CPPFLAGS`) とソースのどちらにも定義がありません。makefw の `PLATFORM_LINUX` は make 変数で、C のマクロにはテストの `makepart.mk` で個別に `DEFINES += PLATFORM_LINUX` とした場合だけなります。

### 個別の実施日時の材料

- C/C++ は、テスト 1 件ごとにテスト バイナリを起動しています (`exec_test_c_cpp.sh`)。
- .NET は、`dotnet test` を 1 回だけ一括実行し、TRX ファイル (`parse_trx_results.py` が解析) から個別の結果を得ています。TRX の各テスト結果には `startTime` 属性 (例: `2026-10-11T10:00:00.1234567+09:00`) があります。現行の `parse_trx_results.py` はこの属性を読んでいません。

**Question**

状態節 (マルチ フェーズ テストの `状態_N` を含む) の本文が空のときに出力する文言を、どれにしますか。

**Context**

現行は「なし」で、見出し「状態」の直下に置くと「状態が存在しない」と読めます。状態節には `[状態]` タグの「…を準備する。」「…を構築する。」のような準備の記述と、サブ手順の「サブ手順 <名前> を実施する。」が並びます。空のときは「前提として書き留めることがない」ことを伝える文言が適します。

```markdown
### 状態

特記すべき状態なし
```

CodeBlock: 案 A の表示

```markdown
### 状態

特別な準備なし
```

CodeBlock: 案 B の表示

```markdown
### 状態

前提とする状態なし
```

CodeBlock: 案 C の表示

**Answer**

選択方式: 単一選択

- [x] A: (推奨) 「特記すべき状態なし」とする。
- [ ] B: 「特別な準備なし」とする。
- [ ] C: 「前提とする状態なし」とする。
- [ ] D: その他。
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)
