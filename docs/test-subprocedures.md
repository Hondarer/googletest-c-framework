# サブ手順をテストの概要とソースへ取り込む

共通関数、fixture の SetUp・TearDown、コンストラクター、デストラクターの処理を名前付きのサブ手順として記載します。  
テストから明示的に参照すると、状態、手順、状態確認、期待確認をテストの概要へ取り込み、定義のソースを抜粋掲載します。  
確認件数は設計上の実施回数であり、呼び出しや条件分岐の実行回数は作成者が確定します。  
確認行為と回数式の基本規則は [テスト フェーズ](about-test-phase.md) を参照してください。

## 開始と終了のコメントで範囲を囲む

```cpp
class SampleTest : public testing::Test
{
    // [サブ手順 名前=SampleTest.CheckResult]
    void CheckResult(const Result& result)
    {
        EXPECT_EQ(CPLAT_OK, result.code); // [確認_正常系] - 結果コードが CPLAT_OK であること。
        EXPECT_TRUE(result.error.empty()); // [確認_異常系] - エラー情報が空であること。
    }
    // [サブ手順終了]
};
```

開始と終了は独立した `//` コメント行に置き、その間を定義内容とします。  
制御用の開始・終了コメントは抜粋から除きます。  
関数全体、クラス内のメソッド全体、または関数内の連続した処理範囲を囲みます。  
定義範囲は入れ子にせず、別のサブ手順を参照します。  
文字列やブロック コメント内のタグは解釈しません。

名前はコメント上の識別子であり、関数名や引数から自動解決しません。  
英字または `_` で始まり、英数字、`_`、`.`、`:` を使います。  
大文字・小文字を区別し、同一テスト ターゲットの入力ソース内で一意にします。  
別ファイルの定義も参照できます。  
入力は対象ディレクトリのテスト ソース、相対パスで取り込む補助ヘッダー、明示的に追加したエビデンス用ソースです。  
シンボリック リンクなどで同じ実体ファイルを参照している場合も、そのファイルは一度だけ読みます。  
testfw が提供する共通サブ手順 `testing.expectExportNamesMatch` は提供元の共通ソースから取り込み、UTF-8 で読みます。  
その他の入力はテスト ターゲットに指定された文字コードを使います。

## 参照の回数は呼び出し回数を表す

```cpp
CheckResult(result); // [サブ手順参照 名前=SampleTest.CheckResult 回数=PARAM*3]
```

`名前` は必須、`回数` と `区分` は任意です。  
属性の順序は問いません。  
回数を省略すると 1 回です。  
式には非負整数、`PARAM`、加算、乗算、括弧、空白を使います。  
テスト側の参照回数は、全パラメーター レコードを通じた合計です。  
`PARAM=4` なら上の参照は 12 回で、正常系 12 件、異常系 12 件を加算します。  
暗黙のパラメーター数の乗算は行いません。

サブ手順内の確認回数と参照回数は、そのサブ手順 1 回あたりの回数です。  
サブ手順内では `PARAM` を使いません。  
入れ子の参照は経路上の回数を掛け合わせます。  
同じ定義を複数箇所で参照した場合は、参照ごとに件数を加算します。  
区分を省略すると定義内の確認タグの正常系・異常系を保持します。  
`区分=正常系` または `区分=異常系` を記載すると、参照した期待確認の分類をその区分へ変更します。  
入れ子の参照にも引き継ぎ、内側の参照に区分がある場合は内側を優先します。  
状態確認の扱いは変えません。  
`[状態確認]` は概要へ取り込みますが件数には加算しません。  
`回数=0` でも定義と参照を検証し、概要には 0 回として表示し、ソースを掲載します。

引数や条件で内部件数が変わる場合は、条件別の範囲を別名で定義し、実施回数を記載します。  
テスト作成者は、サブ手順内の確認を呼び出し側の確認タグへ転記せず、サブ手順参照を記載します。  
同じ呼び出しに確認タグとサブ手順参照を併記すると、二重計上を防ぐためエラーになります。

## 前後の参照はテストに空行を挟まず置く

```cpp
// テストの説明。
// [サブ手順参照 名前=BaseFixture.SetUp]
// [サブ手順参照 名前=SampleTest.SetUp]
TEST_F(SampleTest, Example)
{
    // Arrange
    // Act
    // Assert
    CheckResult(result); // [サブ手順参照 名前=SampleTest.CheckResult]
}
// [サブ手順参照 名前=SampleTest.TearDown]
// [サブ手順参照 名前=BaseFixture.TearDown]
```

テスト宣言直前に連続する参照行を前処理、閉じ括弧直後に連続する参照行を後処理とします。  
参照群とテストの間に空行や別のコメントを置きません。  
各群の記載順を実施順とします。  
.NET では属性を含むメソッド宣言の直前に置きます。  
`位置` 属性は使いません。  
隣接する二つのテストの両方に空行なしで接続する参照群はエラーです。  
所属させない側との間に空行を置いて区別します。  
パラメーター テストの SetUp・TearDown を各レコードで実施する場合は `回数=PARAM` とします。  
スイート全体の処理の確認件数は、各テストへ自動的には割り当てません。

## 概要は参照ごとに展開し、ソースは一度だけ掲載する

定義内の状態、手順、状態確認、期待確認を参照元の対応する概要セクションへ展開します。  
各項目に参照名、参照経路、回数を添え、参照ごとの由来を示します。  
本体内の参照はその時点のサイクルに所属します。  
サブ手順内部のサイクル番号は参照元の番号を変更せず、内部区分として表示します。  
前処理は最初のサイクルの先頭、後処理は最後のサイクルの末尾に展開します。  
確認件数には前後の参照分も含めます。

テスト ソースの後に、直接・間接に参照したサブ手順を最初に参照した順で抜粋掲載します。  
同じ定義のソースは、一つのレポートに一度だけ掲載します。  
定義名と元ファイルのパス、元の行番号を表示します。  
掲載した抜粋を再度集計しません。

抜粋の外側の字下げは、開始タグの行の空白・タブを基準として除きます。  
同じ接頭の字下げを持つ行だけから、その部分を除きます。  
内部の相対的な字下げ、字下げのないプリプロセッサ行、複数行文字列の内容は保持します。  
整形は掲載用コピーだけに行い、元ファイルと解析用ソースは変更しません。

Linux・Windows の条件分岐はテスト本体と同じ規則で評価します。  
定義の開始・終了は無効な分岐でも収集し、無効な分岐の内容は概要と抜粋から除きます。  
プラットフォーム限定の fixture も同じ名前で参照でき、該当しない環境では確認件数を加算しません。  
一部レコード実行時は既存の規則に従い件数を未評価にしますが、概要の展開とソース掲載は行います。  
各レコードのログへ全体件数を重複掲載しません。

## 記述の不備は元ファイルの位置を示して報告する

- 未定義名、重複名、不正な名前、属性の重複、未知の属性。
- 終了タグの欠落、対応しない終了タグ、定義範囲の入れ子。
- 自己参照と相互参照を含む循環参照。
- 不正な回数式、サブ手順内の `PARAM`、通常テストでの `PARAM`。
- 前後の所属が曖昧な参照、テストにもサブ手順にも所属しない参照。
- テストにもサブ手順にも所属しない期待確認タグ。
- 同じ呼び出しへの確認タグとサブ手順参照の併記。

未参照の定義も記述を検証しますが、確認件数には加算しません。  
`[状態確認]` は所属範囲による件数上のエラーから除外します。  
実際の呼び出しと参照記述の一致、コメントのない共通関数内の確認漏れは、作成者とレビューで確認します。
